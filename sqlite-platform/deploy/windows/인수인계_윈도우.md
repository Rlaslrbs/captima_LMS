# 인수인계: Windows 노트북에서 문제노트 돌리기

새 세션에서 이 문서를 먼저 읽고 순서대로 진행해 주세요. 배경과 세부 설명은 같은 폴더의 `윈도우_배포_안내.md`에 있어요.

## 목표
- 맥에서 쓰던 문제노트 서버(Node 24 + SQLite)를 이 Windows 노트북에서 돌린다.
- DB 결정(2026-11-12): **SQLite 유지.** 사람이 많아지면 MySQL로 옮긴다. 옮기는 절차는 `윈도우_배포_안내.md` 10장에 있다. 지금은 MySQL 작업을 하지 않는다.
- 데이터 폴더(`문제노트_플랫폼`)는 OneDrive나 동기화 폴더 밖(예: `C:\문제노트_플랫폼`)에 둔다.
- Cloudflare Tunnel로 바깥(테스터)에서 접속되게 한다.
- 재부팅 후에도 자동으로 살아나고, 매일 DB를 백업한다.

## 이미 준비된 것
- `deploy/windows/start-all.ps1`: 서버 + 터널을 같이 켬 (노트북 잠들지 않게 막음)
- `deploy/windows/register-tasks.ps1`: 로그온 자동 시작 + 매일 03:00 백업 등록
- `deploy/windows/backup.mjs`: DB 백업 (최근 30개 보관, `BACKUP_DEST`가 있으면 다른 폴더에도 복사)
- `deploy/windows/config.yml.example`: 고정 주소용 Cloudflare 설정 예시
- PowerShell 스크립트는 맥에서 문법 검사를 못 했다. 처음 실행할 때 오류가 나면 `data\logs\`의 로그를 보고 고친다.

## 아직 안 된 것 (순서대로)

1. **Node.js 확인**
   - `node -v` 결과가 v24.x (최소 22.13)인지 확인. 없으면 `winget install OpenJS.NodeJS.LTS`.
   - 설치 뒤에는 PowerShell을 새로 연다.

2. **cloudflared.exe 배치**
   - Windows용 `cloudflared-windows-amd64.exe`를 받아 `tools\bin\cloudflared.exe`로 둔다.
   - 맥의 `tools/bin/cloudflared`는 쓸 수 없다.

3. **데이터 옮기기**
   - 맥의 `data\app.db`, `data\admin_path.txt`를 이 노트북의 `data\` 폴더로 복사한다.
   - 학생 기록이므로 git에 올리지 않는다. `.gitignore`에 `data/`가 있는지 확인한다.
   - 복사하기 전 `data\`가 이미 있으면 덮어쓰기 전에 사용자에게 확인한다.

4. **로컬 확인**
   - `node server\server.js`를 켜고 `http://127.0.0.1:4000/`이 열리는지 확인한 뒤 끈다.
   - 관리자 비밀 주소 값은 채팅이나 문서에 옮겨 적지 않는다.

5. **바깥 주소 정하기 (사용자에게 확인)**
   - 임시 주소(`trycloudflare.com`, 켤 때마다 바뀜)로 먼저 갈지, 도메인이 있어서 고정 주소로 갈지 묻는다.
   - 임시 주소면 `start-all.ps1`의 `$TunnelName`을 `""`로 바꾸고 `start-all.ps1`을 실행한다.
   - 고정 주소면 `cloudflared tunnel login`(브라우저 로그인, 사용자가 직접 해야 함), `tunnel create munje-note`, `config.yml` 작성, `tunnel route dns`를 차례로 한다. `<tunnel-id>`와 도메인은 사용자에게 받는다.

6. **자동 시작·백업 등록**
   - 관리자 권한 PowerShell에서 `register-tasks.ps1`을 실행한다. 등록 뒤 작업 스케줄러에서 `문제노트-시작`, `문제노트-백업`이 보이는지 확인한다.

7. **노트북 설정 안내 (사용자가 직접)**
   - 절전 사용 안 함, 덮개 닫을 때 동작 없음, 활성 시간 설정, 자동 로그온.
   - 이 설정은 사용자가 직접 바꿔야 한다. 대신 방법을 안내한다.

## 하지 말 것
- 테스트 스위트나 검증 스크립트를 임의로 돌리지 않는다. 사용자가 요청할 때만 한다.
- `data/app.db`를 팀원이나 외부에 주지 않는다. 학생 기록을 바꾸지 않는다.
- 관리자 화면을 바깥(Tunnel)에 열지 않는다. `ADMIN_REMOTE=1`은 설정하지 않는다.
- 사용자 확인 없이 `data\` 덮어쓰기, 기존 프로세스 강제 종료, 작업 스케줄러 삭제를 하지 않는다.

## 끝나면 사용자에게 보고할 것
- 서버가 `127.0.0.1:4000`에서 열리는지
- 바깥 주소(임시 또는 고정)가 무엇인지 (주소만, 관리자 비밀 주소는 제외)
- 자동 시작과 백업 작업이 등록됐는지
- 아직 사용자가 직접 해야 하는 것 (노트북 전원 설정, 로그인 등)
