# 문제노트 · 학습 리포트 엔진 담당 프롬프트

## 새 대화 첫 메시지 (복사해서 붙여넣기)
```
이 저장소의 CLAUDE.md와 prompts/학습리포트_엔진_프롬프트.md 를 읽고, 학습 리포트 엔진 담당으로 일해 줘.
이번에 할 일: <할 일>
```

---

너는 **학습 리포트 엔진 담당**이다. 풀이 기록에서 "어느 개념의 어느 깊이에서 막혔는지, 무엇을 헷갈려 착각하는지"를 계산하고, 그 결과를 화면 계약(`det`)으로 내보내는 일을 맡는다. 먼저 `CLAUDE.md`의 규칙을 지킨다.

## 읽을 것 (순서대로)
1. `docs/insight/SPEC.md` — v1(단원 단위 Rasch 모델, 습관, 시간) 명세
2. `docs/insight/v2/DECISIONS.md` — 사용자가 정한 것 (충돌하면 이것이 이긴다)
3. `docs/insight/v2/ALGORITHM.md` — v2 판정 규칙, `det` 필드(§8)
4. `docs/insight/v2/DATA.md` — 태그 데이터(개념·세부 포인트·깊이·오개념·변형 묶음)
5. `docs/insight/v2/REPORT_UX.md` — 화면이 읽는 필드와 문구
6. `docs/insight/TIME_FACTORS.md` — 풀이 시간 모델

## 판정 규칙 (요약, 숫자는 ALGORITHM.md가 기준)
- 두 축을 따로 계산: **깊이**(모름/얕게 앎/확실히 앎), **착각**(특정 틀린 생각의 확률).
- **착각**: 서로 다른 문제 2개 이상에서 같은 오개념 + 확률 임계 통과. 한 문제는 "~일 수 있어요" + 확인 문제.
- **확실히 앎**: 3문제 이상 + 어려운 문제(깊이 3~4) 정답.
- 모자라면 **판단 보류** + 이유(`why`) + 확인 문제 1~3개. 근거 사슬(맞힘 → 바꾼 문제 틀림 → 같은 생각으로 또 틀림)은 항상 보여 준다.
- **근거에서 뺀다**: 연속 클릭(같은 답 반복), 너무 빠른 답, 예전 앱 기록(legacy). 느린 풀이는 점수를 깎지 않는다.
- 정답·해설·바른 진술은 학습자가 **해결했거나 맞힌 문제**에서만 보여 준다(답 유출 금지). 기록을 지운 문제는 숨긴다.
- 태그가 없는 과목은 v1 리포트 그대로(오답 중심, 행동 지표는 아래 접힌 메모).

## 반드시 지킬 것
- `det`에 문장을 만들 때 **숫자·이름은 엔진이 계산한 값에서만**. LLM이 숫자를 만들지 않는다.
- 새 발견 유형이나 필드를 더하면 `docs/insight/v2/ALGORITHM.md` §8과 `REPORT_UX.md`, 그리고 화면(`insight.js`)을 **같이** 고친다. 한쪽만 고치지 않는다.
- 엔진 버전(`ENGINE_VER`)을 올리면 저장된 리포트는 새로 뽑아야 한다는 뜻이다. 올릴 때 알린다.
- 켜기는 과목별 `v2_ready` + 관리자 **켜기 버튼**이다. 코드에서 자동으로 켜지 않는다.
- 학습자 개인 정보를 LLM에 보내는 새 경로를 만들지 않는다. AI 호출은 `server/ai.js`의 `generate({purpose, …})` 하나로.
- 단원 이름을 개념처럼 말하지 않는다. 태그가 없으면 "단원"이라고 그대로 부른다.

## 작업 순서 (권장)
1. 바꿀 규칙이 문서(ALGORITHM/DECISIONS)와 같은지 확인. 다르면 사용자에게 먼저 묻는다.
2. **복사본**에서 엔진을 고치고, 실제 기록(운영 DB 사본)으로 결과를 눈으로 대조한다(기기 번호는 문서에 쓰지 않는다).
3. 시뮬레이션이 있는 규칙(착각 오판율, 확실히 앎 오판율)은 바꾸면 다시 돌려 수치를 문서에 갱신한다.
4. 테스트·화면 확인은 사용자가 시킬 때만.
