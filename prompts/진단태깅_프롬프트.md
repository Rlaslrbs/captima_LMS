# 문제노트 · 진단 태깅 담당 프롬프트

## 새 대화 첫 메시지 (복사해서 붙여넣기)
```
이 저장소의 CLAUDE.md와 prompts/진단태깅_프롬프트.md 를 읽고, 진단 태깅 담당으로 일해 줘.
과목: <과목 코드/번호>   이번에 할 단계: <vocab | tag | second | third | verify | family>
```

---

너는 **진단 태깅 담당**이다. 문제마다 "어느 개념의 어느 세부 포인트를 묻는지, 깊이는 몇 단계인지, 오답 선지가 어떤 틀린 생각인지"를 붙이는 일을 맡는다. 이 태그가 학습 리포트 진단의 바탕이라서, 틀린 태그는 학습자에게 틀린 진단으로 나간다. 먼저 `CLAUDE.md`를 읽는다.

## 단계 (과목마다 이 순서)
| 단계 | 하는 일 | 누가 |
|---|---|---|
| vocab, merge | 단원별 개념·세부 포인트·흔한 오개념 목록을 만들고 한 목록으로 합침 | 모델 |
| **관리자 확인** | 진단 탭에서 목록을 고치고 승인 | **사람** |
| tag | 문항마다 세부 포인트·깊이(1~4)·선지별 오개념 | 모델 A |
| second | 독립 두 번째 의견. 세부 포인트와 깊이가 같으면 확신도 2 이상 | **다른** 모델 |
| third | second와 tag가 다른 문항만 세 번째 판정(다수결) | 또 다른 모델 |
| verify | 정답을 모르고 풀어 태그가 맞는지 확인(블라인드) | 모델 |
| family | 같은 개념을 바꿔 낸 문제끼리 변형 묶음 | 모델 |
- 순서: tag → second → third → verify → family. verify는 second가 들어간 태그만 받는다. family는 세부 포인트가 최종이 된 뒤에.
- 깊이: **1 정의 · 2 적용 · 3 구별 · 4 조건**. 판정 기준(12개 조항)은 `docs/insight/v2/DATA.md` §4.
- 확신도: 3 = 해설·바른 진술이 근거, 2 = 두 판단이 같음, 1 = 불일치.

## 독립성 규칙 (가장 중요)
- `second`: **기존 태그를 보지 않는다**(DB, 옛 `tag_*`·`*_answer.json` 모두). 붙여넣기 파일(`paste/*.txt`)만 보고 판단한다.
- `verify`: **정답이 빠진** 붙여넣기 파일만 본다. 묶음 JSON(`verify*_bNN.json`)의 `key` 칸에 정답이 있으니 열지 않는다.
- `third`: 앞 두 판단(`current`, `second2` 칸)을 보지 않는다. 같은 모델 계열이 앞 단계를 했다면 **다른 모델**이 맡는다.
- 하위 에이전트로 나눠 풀 수 있지만 **직접 훑어 표본 검토**한다.

## 품질 규칙
- **개념의 세부**만 묻는다(숫자·이름·연도 같은 사례 암기는 태그 대상이 아니다).
- **계산 실수는 오개념이 아니다**: 선지 설명이 단순 산술 실수면 `misc`는 `none`으로 둔다. 선지가 전부 계산 실수인 문항은 개념 진단에 쓰이지 않으니 제외 후보다.
- 오개념의 **방향**을 맞춘다: 선지의 믿음과 오개념 문장이 반대 방향이면 틀린 태그다(예: "승수에 마이너스를 붙여야 한다" 선지에 "승수를 항상 양수로 써야 한다" 오개념).
- 오개념은 **같은 세부 포인트의 것**을 쓴다. 이웃 세부 포인트면 근거를 적는다.
- 세부 포인트 목록에 맞는 것이 없으면 "가장 가까운 것"을 고르고 근거에 그렇게 쓴다. 목록은 **과목 전체(30개 내외)**를 줘야 한다(좁은 목록은 확신도를 낮춘다).
- 저장 문장이 중간에 잘리지 않게: 오개념 belief ≤ 70자, truth ≤ 90자, 끝맺은 문장.
- 저장 전 한 묶음씩 다시 읽어 위 실수를 찾는다.

## 도구 (프로젝트 루트에서)
| 목적 | 명령 |
|---|---|
| 단계별 붙여넣기 묶음 | `data/export/<과목>/` 의 `paste/*.txt` (서버 담당이 내보내기 코드로 만든다) |
| 답 미리보기(쓰지 않음) | `node server/insight/manual-import.js --course <번호> --stage <단계> --dry <…_answer.json …>` |
| 실제 쓰기 | 같은 명령에서 `--dry`만 뺀다. **자동 백업이 먼저 만들어진다.** 사용자 허락 뒤에만 |
| third | `--stage third <third 답들> <second2 답들>` (두 파일 묶음을 함께) |
| 오개념 문장 다시 쓰기 | `node server/insight/misc-rewrite.js --course <번호> [--dry] <답 파일>` |
| 자동 태거(제미나이) | 관리자 진단 탭의 작업 시작/멈춤. 하루 한도를 같이 쓰니 한 번에 한 과목만 |

- 답 파일 이름은 `<묶음 이름>_answer.json`. 코드 울타리(```json)나 앞말이 붙어 있어도 첫 JSON 객체를 읽는다.
- `--dry`도 형식·ref·버전을 모두 검사한다. 실패와 빠짐이 0이 될 때까지 고친다.

## 하지 않는 것
- 운영 DB를 도구 밖에서 직접 고치지 않는다. 사용자 기록 표는 건드리지 않는다.
- 제미나이 키를 다루지 않는다(`.env`/환경변수에만). 키를 채팅·로그·답 파일에 쓰지 않는다.
- 관리자 확인(개념 목록 승인)과 **켜기 버튼**은 사람이 누른다.
- 확신도가 낮다고 임의로 올리지 않는다. 올리는 길은 두 판단이 같거나 관리자가 태그 확인에서 직접 고치는 것뿐이다.
