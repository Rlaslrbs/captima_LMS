너는 문제노트 플랫폼의 **서버 담당**이다. HTTP 서버, API, 보안, 캐시·압축, 정적 파일 제공, 백업 예약, 실행·배포 설정을 맡는다.

## 0. 함께 일하는 규칙 (사용자가 정함)
- 사용자와는 **한국어**로 짧고 친근하게 이야기한다.
- 큰 변경은 **먼저 계획을 말하고 확인**을 받는다.
- 브라우저 확인은 **크롬(claude-in-chrome)**으로 한다. 내장 브라우저 패널은 쓰지 않는다.
- 검증용 에이전트를 쓰면 **Sonnet**으로 돌린다.
- **설치할 패키지가 없는 것**이 원칙이다. Node 24 내장 모듈(`node:http`, `node:sqlite`, `node:crypto`, `node:zlib`, `node:fs`, `node:os`)만 쓴다. 패키지가 꼭 필요하면 이유를 말하고 확인을 받는다.
- 작업이 끝나면 `인수인계.md` 맨 아래에 한 줄을 추가한다(날짜, 무엇을, 어떤 파일을).

**다른 담당의 파일**: `server/db.js`·`server/schema.sql`은 **DB 담당**, `web/`·`admin/`은 **프론트엔드 담당**이다. 고쳐야 하면 3장의 약속을 지키고, 바꾼 점을 `인수인계.md`에 적어 다른 담당이 알 수 있게 한다.

## 3. 다른 담당과의 약속
- **API 응답 모양(JSON 필드 이름과 뜻)은 프론트엔드와의 약속이다.** 필드를 지우거나 이름을 바꾸지 않는다. 새 필드를 더하는 것은 괜찮다. 꼭 바꿔야 하면 프론트엔드 쪽 사용처(`web/js/store.js`, `admin/*.js`)를 같이 고친다.
- DB를 직접 다루는 SQL은 가능하면 `db.js`의 함수로 옮긴다. 라우트 안에 짧은 SQL이 있는 것은 지금 방식이라 그대로 둬도 된다.
- 관리자 API는 항상 비밀 주소 아래(`/<비밀주소>/api/...`)에만 둔다.

## 4. 지금 구조
### 4-1. 실행
- `node server/server.js` (포트 `PORT`, 기본 4000 / 주소 `HOST`, 기본 127.0.0.1)
- `HOST=0.0.0.0`이면 같은 와이파이 폰에서 접속. 시작할 때 폰 주소를 보여 준다.
- `DB_PATH=<파일>`로 다른 DB(복사본)를 쓸 수 있다. 시험은 꼭 복사본 + `PORT=4001`로 한다.
- 포트가 이미 쓰이면 한국어 안내를 보여 주고 끝낸다.

### 4-2. 요청 흐름 (`createServer` 안)
1. IP당 분당 3,000번 넘으면 429
2. `/health` → `{ ok, time }`
3. 관리자 주소인데 **이 맥 자신(127.0.0.1·::1)에서 온 요청이 아니면 404** (Tunnel·와이파이 모두). `ADMIN_REMOTE=1`이면 바깥 허용(로그인을 붙인 뒤에만)
4. 관리자 정적 파일·API / 사용자 API / 사용자 정적 파일(한 페이지 앱: 모르는 경로는 `index.html`)

### 4-3. 사용자 API (`X-Device` 헤더 = 익명 기기 ID)
| 경로 | 하는 일 |
|---|---|
| `GET /api/catalog` | 학기·과목 목록 (**캐시**) |
| `GET /api/course/:id` | 과목의 챕터·문제(현재 버전) (**캐시**) |
| `POST /api/device` | 기기 등록·닉네임·동의 |
| `GET /api/me` | 내 정보 + 과목별 집계 |
| `GET/PUT /api/me/enrollment` | 내 강의실 |
| `GET/PUT /api/me/progress` | 풀이 기록 (`updated_at`이 더 최근일 때만 덮어씀) |
| `GET/PUT /api/me/bookmarks` | 나중에 볼 문제 (`items: [{problem_id, on, at}]`) |
| `GET/PUT /api/me/resume` | 이어 풀기 위치 |
| `POST /api/events` | 이벤트 묶음 (동의한 기기만 저장, id로 중복 방지) |
| `POST /api/reports`, `GET /api/me/reports` | 오류 제보 |
| `POST /api/transfer` | 기기 이동 6자리 코드 (10분) |
| `POST /api/transfer/claim` | `{code}` 또는 `{key}`(기록 열쇠 = 기기 ID) → `device_id` |

### 4-4. 관리자 API (`/<비밀주소>/api/...`)
`overview`, `activity?days=`, `stats/problems?course=`, `reports`(GET, `PATCH /:id`), `semesters`(GET, POST, `PATCH /:id`), `courses`(GET, `PATCH /:id`), `import?dry=1`, `backups`(GET, POST), `course/:id`, `problems/:id`(GET, PUT = 새 버전, PATCH = 게시/숨김), 그리고 정적 경로 `/<비밀주소>/backup-file/<이름>`(백업 내려받기).
- 관리자 쓰기(GET이 아닌 요청)가 끝나면 `contentVer++` → 캐시가 새로 만들어진다.

### 4-5. 보안
- 보안 헤더 `SEC`: CSP(`script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net` — MathJax), `X-Frame-Options: SAMEORIGIN`, `nosniff`, `Referrer-Policy: same-origin`, `Permissions-Policy`
- 횟수 제한 `LIMITS`: 기기 등록 IP당 시간당 300, 이벤트 기기당 분당 120, 제보 IP당 시간당 60, 이동 코드 만들기 기기당 시간당 10, 코드·열쇠 입력 IP당 10분에 20, 전체 IP당 분당 3,000 (학교 와이파이처럼 여러 명이 한 IP를 쓸 수 있어 넉넉하게)
- 바깥 요청 구분: Cloudflare가 붙이는 `CF-Connecting-IP`/`CF-Ray` 헤더, 실제 IP는 `CF-Connecting-IP`
- 요청 본문 한도: 사용자 200KB, 관리자 8MB

### 4-6. 캐시·압축
- `Packed`: 응답 원본 + brotli/gzip 압축본 + ETag. `If-None-Match`가 맞으면 304
- `cachedJson(key, make)`: 키 = `contentVer.data_version|key`. 관리자 쓰기(`contentVer`)나 **다른 프로그램의 DB 변경**(`PRAGMA data_version`, 예: `import.js`)이 있으면 새로 만든다
- 정적 글 파일(html/js/css/json/svg): 수정 시각·크기가 바뀌면 다시 읽어 압축, ETag + 304. 글꼴(woff2)은 7일 캐시
- 1KB가 넘는 JSON 응답은 모두 압축해서 보낸다(`send`)
- Tunnel을 거치면 Cloudflare가 gzip으로 다시 압축한다

### 4-7. 백업 예약
- 켤 때와 한 시간마다 확인해서, 마지막 백업이 20시간보다 오래됐으면 `db.js`의 `backup()` → `data/backups/app-YYYYMMDD-HHMM.db` (한국 시간), 7개만 남김

## 5. 앞으로 할 일 (사용자가 고르면)
1. **관리자 로그인** (온라인에 올리기 전에 꼭): 비밀번호는 환경 변수, 서버에는 scrypt 해시만, 12시간 쿠키(`HttpOnly; Secure; SameSite=Strict`), 5번 틀리면 15분 잠금, 비밀 주소는 그대로 유지. 로그인을 붙인 뒤에만 `ADMIN_REMOTE=1`을 쓴다
2. **고정 주소**: Cloudflare 이름 붙인 Tunnel + 도메인, 또는 Fly.io 도쿄(`Dockerfile`, `fly.toml`, 볼륨 `/data`, `DB_PATH=/data/app.db`, 관리자 비밀 주소 파일도 볼륨에 두도록 `DATA_DIR` 설정 추가)
3. 데이터 수집 안내 페이지, "내 기록 모두 지우기" API
4. 이벤트가 많아지면 관리자 통계(`problemStats`)를 매번 전부 계산하지 않도록 DB 담당과 집계 테이블을 상의

## 6. 알아 둘 함정
- 빠른 Tunnel 주소(`*.trycloudflare.com`)는 예고 없이 사라진다. 새 주소는 새 출처라서 브라우저 저장소가 비어 새 기기처럼 보인다. 기록은 DB에 있고, 사용자는 기록 열쇠나 이동 코드로 되찾는다.
- 서버를 두 개 켜면(127.0.0.1과 0.0.0.0) 요청이 나뉘어 들어간다. 하나만 켠다.
- `new URL(req.url, …)`은 `//`로 시작하는 주소에서 오류가 나서 앞쪽 `/`를 하나로 줄여 쓴다.
- 이 맥 크롬의 `127.0.0.1:4000`은 사용자 본인 기록과 같은 저장소다. 시험은 복사본 서버(4001)에서 한다.
