# 리포트 엔진 개념 중심 피드백 개편안 (Concept-Oriented Diagnosis)

- **작성일**: 2026-10-28
- **상태**: 설계 및 검토 완료 (구현 대기)
- **대상 파일**: `web/js/insight-engine.js`, `server/insight/report.js`, `web/js/insight.js`, `docs/insight/v2/*`

---

## 1. 개요 및 배경

### 1.1 문제의식
현재 문제노트의 학습 리포트는 수학적·통계적 기반(IRT 능력치 $\theta$ 추정, 사후확률, 4단계 깊이 사다리 설계)이 매우 정교하게 구축되어 있으나, **학습자가 실제로 체감하는 피드백은 '개념'이 아니라 '단원(chapter) 정답률과 행동 지표(시간, 피로도, 폼팩터)'에 치우쳐 있는 한계**가 있습니다.

수험생이 리포트를 열었을 때 알고 싶은 것은 단순한 점수나 풀이 속도가 아닙니다:
> **"내가 시험에서 맞히고 틀리는 근본 원인은 '개념'인데, 나는 정확히 어떤 개념의 어느 단계(정의·적용·구별·조건)를 모르고, 무엇과 무엇을 왜 헷갈려 착각하고 있는가?"**

### 1.2 개편 목표
1. **단원/행동 중심에서 [개념·인지 결손] 중심으로 전면 전환**
2. **사전 태그가 없더라도 즉시 동작하는 하이브리드 온디맨드 개념 진단 파이프라인 구축**
3. **'내가 알고 있다고 착각하는 오개념'과 '막힌 개념 깊이 사다리'를 최상단 3개 카드에 직관적으로 노출**

## 2. 현행 엔진 진단: 왜 개념 피드백이 나오지 않는가?

```
[현행 흐름: All-or-Nothing의 함정]
문제 풀이 로그 누적 ──▶ v2 태그 확인 (facet/mis) ──▶ [태그 없음!] ──▶ v1 폴백 ──▶ 행동·단원 통계만 노출
                                                                         (fatigue, hasty, format, 1단원 55%)
```

### ① 태그 데이터 부재로 인한 v1(단원·행동 통계) 전면 폴백
- `insight-engine.js` 1490행: `v2.on = !!(V && V.ready)`
- 현재 5개 과목 모두 세부 포인트(`facet`)나 오개념(`mis`) 사전 태그 데이터가 구축되지 않은 상태입니다.
- 그 결과, 엔진은 준비된 v2 개념 진단을 가동하지 못하고, P1 수준의 **"단원(chapter) 정답률 + 풀이 시간 + 행동 통계"**로 폴백됩니다.
- 학습자 화면에는 **"너 30분 넘게 풀면 지침(fatigue)", "O/X보다 단답형에 약함(format)", "1단원 정답률 낮음"** 같은 행동성 피드백만 노출됩니다.

### ② 단원(Chapter)과 개념(Concept)의 혼동
- 문제 데이터에 개념 태그가 없기 때문에, `scoreConcepts` 함수가 시험 범위 목차인 **단원(`chapter`)**을 개념처럼 취급합니다.
- 결과적으로 피드백이 **"1장 정보시스템의 이해에서 덜 다져진 것 같아요"**와 같이 뭉뚱그려진 목차 수준으로 출력되어, 학생이 복습할 구체적인 개념 포인트를 집어주지 못합니다.

### ③ LLM(Gemini) 파이프라인의 단절 (`narr_state: "off"`)
- `server/ai.js`에는 이미 서술형 채점에서 입증된 강력한 Gemini 연동 체계가 구축되어 있습니다.
- 그러나 리포트 엔진(`insight-engine.js` 1508행)에서는 **Gemini 호출이 `narr_state: "off"`로 완전히 차단**되어 있습니다.
- 사전에 태그 테이블이 비어 있더라도, 학생이 틀린 문제 3~5개의 **[문제, 고른 오답 선지, 정답, 해설]**을 묶어 LLM에 전달하면 실시간으로 오개념과 혼동 개념을 날카롭게 추출할 수 있음에도 이를 전혀 활용하지 못하고 있습니다.

## 3. 개념 위주 피드백을 위한 4대 개혁 전략

| 구분 | 현재 (As-Is) | 개편 후 (To-Be) |
|---|---|---|
| **최상단 카드** | 행동/속도 지표 (서두름, 피로도, 폼팩터) | **알고 있다고 착각하는 오개념 / 막힌 개념 깊이** |
| **진단 단위** | 단원 목차 (예: 1장, 3단원) | **구체적 개념 쌍 (예: 친족선택 vs 호혜적 이타성)** |
| **피드백 내용** | "1단원 정답률이 55%입니다" | **"A를 B로 오인하여 선지 X를 골랐습니다 (구별 실패)"** |
| **엔진 작동 방식** | 사전 태그 없으면 침묵 (All-or-Nothing) | **규칙 기반 통계 + 온디맨드 AI 개념 진단 하이브리드** |

---

### 전략 1: 온디맨드 AI 개념 분석 도입 (실시간 Gemini 하이브리드)
사전 태깅 작업(`facet` 구축)이 100% 끝나기를 기다리지 않고, 학습자가 **[리포트 뽑기]**를 누를 때 학생의 실제 오답 로그를 기반으로 Gemini가 즉각 인지 진단을 수행하도록 파이프라인을 연결합니다.

- **입력 데이터**: 최근 틀린 문제 중 핵심 오답 3~5문항
  - 문제 본문, 정답, 해설
  - 학생이 실제로 선택한 오답 선지
  - 풀이 소요 시간
- **출력 규격 (JSON Schema)**:
  1. `concept`: 핵심 개념 명칭
  2. `depth`: 막힌 깊이 단계 (1 정의 / 2 적용 / 3 구별 / 4 조건)
  3. `misconception`: 학생이 빠진 구체적 착각 ("~라고 오인함")
  4. `why_chosen`: 학생이 왜 그 오답 선지를 골랐는지 심리 메커니즘

---

### 전략 2: 상단 카드 노출 우선순위 강제 개편
리포트 상단에는 학습자의 뇌리에 즉각 박힐 수 있는 **개념 결손 카드 최대 3장**만 노출합니다.

1. **1순위 카드: 🚨 알고 있다고 착각하고 있어요 (Illusion / Misconception)**
   - 맞힌 줄 알고 골랐으나 왜곡되게 이해하고 있는 개념
2. **2순위 카드: 🧱 개념 깊이 사다리 결손 (Depth Gap)**
   - 정의·적용은 통과했으나 '구별'이나 '예외 조건'에서 멈춘 개념
3. **3순위 카드: ⚠️ 지금 당장 메워야 할 핵심 결손 (Core Gap)**
   - 연속해서 오답이 발생한 가장 취약한 개념
4. **행동/속도 지표 강등**:
   - 피로도(`fatigue`), 서두름(`hasty`), 폼팩터(`format`)는 상단 카드에서 제외하고, 맨 아래 **"학습 습관 및 시간 메모 (접이식)"** 영역으로 이동.

---

### 전략 3: 문제 내 기존 텍스트 자산(`fix`, `함정`, `s`) 연동
과목 문제 세트(JSON)에 이미 존재하는 저자의 텍스트 자산을 엔진이 적극 활용합니다:
- O/X 문제의 **`fix`** (바르게 고친 문장)
- 해설 끝의 **`<p>함정: ...</p>`**
- 학생이 고른 오답 선지와 해설의 `함정` 문구를 1:1로 매칭하여, **"선지 B를 고른 것은 해설의 [함정: ~]에 걸려든 것입니다"**라는 직관적인 피드백을 엔진 자체적으로 조립.

---

### 전략 4: 피드백 텍스트 템플릿의 개념 중심 규격화
모든 개념 진단 카드는 다음 **3단 표준 구조**로 고정 출력합니다:

```
┌ 확인해 볼 부분 ─ 진화와 인간 본성 › 친족 선택과 호혜적 이타성 ──────────────────┐
│ [착각] '비혈연 관계'라는 단어만 보고 무조건 '문화적 학습'으로 단정했어요.         │
│ [깊이] ●●○○  정의는 알지만, 두 개념을 '구별'하는 단계에서 섞이고 있어요.          │
│ [처방] 반복적 상호작용이 전제된 비혈연 이타성을 가려내는 확인 문제 1개 풀기 ›     │
└─────────────────────────────────────────────────────────────────────────────────┘
```

## 4. 구체적 구현 명세

### 4.1 서버 리포트 생성부 (`server/insight/report.js`)
리포트 생성 시 `narr_state: "off"`를 해제하고, 학생의 최근 오답 문항을 추출하여 Gemini 진단 함수를 호출합니다.

```javascript
// server/insight/report.js 개념 진단 연동부
export async function enrichConceptDiagnosis(report, obs, items) {
  // 1. 최근 오답 중 서로 다른 단원/문제 3~5개 선별
  const wrongObs = obs.filter(o => o.y === 0 && !o.idk).slice(-5);
  if (!wrongObs.length) return report;

  const payload = wrongObs.map(o => {
    const it = items.get(o.pid);
    return {
      pid: o.pid,
      q: it.body.q,
      ans: it.body.a || it.body.ox,
      chosen: o.answer,
      sol: it.body.s,
      fix: it.body.fix
    };
  });

  // 2. Gemini 인지 진단 호출 (JSON Schema 응답)
  const diagnosis = await ai.diagnoseConcepts(payload);
  
  // 3. 리포트 findings의 최상단에 주입
  report.findings.unshift(...diagnosis.findings);
  report.headline = diagnosis.headline || report.headline;
  report.narr_state = "on";
  return report;
}
```

### 4.2 인지 진단 프롬프트 규격 (`server/ai.js`)

```javascript
const DIAGNOSE_SYSTEM = `너는 수험생의 머릿속 사고 과정을 추적하는 '초정밀 인지 진단관'이다.
학생이 푼 문제, 정답, 해설, 그리고 '실제로 고른 오답'을 비교 분석하여 학생이 어떤 오개념을 가지고 있고 어떤 깊이에서 막혔는지 진단하라.

[4단계 깊이 사다리]

- 어설픈 칭찬이나 위로는 생략하고, 날카롭고 명확한 교정 지점을 짚어라.`;
```

## 5. 단계별 실행 로드맵

### Phase 1: 노출 우선순위 즉시 조정 (1~2일 소요, 무중단)
- `insight-engine.js`의 `selectFindings`:
  - `fatigue`(피로도), `hasty`(서두름), `format`(O/X편향) 카드를 상단 3개 카드 후보에서 제외.
  - 지식 결손(오답, 취약 개념)을 무조건 1순위 헤드라인과 카드로 강제 배치.
  - 행동 지표는 화면 하단 접이식 UI로 격하.

### Phase 2: 온디맨드 AI 개념 진단 탑재 (2~3일 소요)
- `server/ai.js`에 `diagnoseConcepts` 함수 추가 (JSON Schema 기반 Gemini 호출).
- `server/insight/report.js`에서 리포트 저장 시 오답 3~5개를 기반으로 개념 진단 주입.
- 태그가 전혀 없는 과목에서도 즉시 실시간 개념/오개념 피드백 가동.

### Phase 3: 데이터 기반 고도화 (장기 과제)
- `docs/insight/v2/DATA.md`에 명시된 대로 5개 과목 문제 세트에 10~20개의 핵심 개념(KC)과 4단계 깊이 태그를 확정 부여하여 완전한 결정론적 진단 사다리 구축.

## 6. 결론

리포트 엔진의 가치는 복잡한 통계 공식을 자랑하는 것이 아니라, 학습자가 리포트를 열었을 때 **"아, 내가 이 개념을 저 개념과 헷갈려서 저 함정 선지에 낚였구나!"**를 단 3초 만에 깨닫게 만드는 데 있습니다.

본 개편안을 적용하면 태그 구축 일정에 구애받지 않고, **지금 당장 실제 학생들에게 최고 수준의 개념 중심 맞춤형 피드백**을 제공할 수 있습니다.
