## 2. 파일 구조

최상위는 **배치 파일 이름을 키로 한 객체**예요. 값은 그 배치의 답 목록이에요.

```
{
  "tag_mc_1.1-2_b01.json":  [ {ref, rationale, facet, depth, depth_why, options:[…]}, … ],
  "tag_mc_exam_b01.json":   [ … ],
  "tag_mc_exam_b02.json":   [ … ],
  "tag_mc_exam_b03.json":   [ … ],
  "tag_ox_2.5_b01.json":    [ {ref, …, ox:{…}, new_misc:[…]} ],
  "tag_ox_exam_b01.json":   [ … ]
}
```

- **MC 문항:** `options`에 **틀린 선지**만 들어 있어요. 정답 선지는 없어요. 선지마다 `idx`, `belief_if_chosen`(그 선지를 고르면 가진 생각), `misc`(오개념 코드, 없으면 `none`), `d`(깊이 판정), `src`(근거 출처), `err`(오류 유형)이 있어요.
- **OX 문항:** `ox` 객체에 `statement_true`, `planted_error`, `misc`, `reverse_misc`, `d`, `err`가 있어요.
- **공통:** `ref`(p+문제번호), `rationale`, `facet`(세부 포인트), `depth`(1~4), `depth_why`(루브릭 코드) 가 있어요.
- **`new_misc`:** 승인된 46개 오개념에 없는 새 오개념 제안이에요. 현재 1건(p608)이에요. 승인 목록에 자동으로 들어가지 않아요.

## 5. 확인이 필요한 부분 (사람 검토 권장)

1. **오개념과 세부 포인트가 어긋나는 경우 2건**
   - p749: 세부 포인트 `lu.f1`인데 선지 오개념 `m024`는 `elim.f1` 소속이에요.
   - p800: 세부 포인트 `lineplane.f1`인데 선지 오개념 `m006`은 `lineplane.f2` 소속이에요.
   - 둘 다 이웃 세부 포인트라 틀렸다고 단정할 수는 없어요. 검토 때 보세요.
2. **계산 실수로 분류된 선지가 많아요.** `err: calc_slip`, `src: inferred`인 선지가 많고 오개념이 `none`이에요. 이런 선지는 개념 진단에 쓰이지 않아요. 진단 가치가 낮다는 뜻이에요.
3. **새 오개념 제안 1건(p608).** "해가 없는 선형시스템에서도 일반해 공식을 쓸 수 있다고 생각함". 승인 전에는 리포트에 쓰지 않아요.
4. **OX 문항 3건** 중 p608은 `statement_true: false`예요. 나머지 두 건은 참 문장이에요.
